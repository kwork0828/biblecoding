## 편별 상세

### EP01 코드보다 먼저, 명세서 한 장
- 핵심 메시지: AI에게 "앱 만들어줘"보다 "이 명세대로 만들어줘"가 결과가 좋다.
- 등장 자료: SPEC.md 목차 12개 절, 데이터 모델(Verse), 저작권 절, 구현 순서 4단계
- 따라 치기 프롬프트:
  - `성경 암송 웹앱의 명세서(SPEC.md)를 써줘. 인터넷 없이 동작하고, 한국어·영어 구절을 간격반복으로 외우는 앱이야. 기술 스택, 데이터 모델, 화면, 저작권, 구현 순서를 포함해줘.`
  - `구현 순서를 4단계로 나누고, 각 단계가 끝날 때마다 동작하는 상태를 유지하게 해줘.`
- 막힐 지점과 해결:
  - "명세서를 어떻게 읽어야 할지 모르겠다" → 12개 절 중 개요·화면·구현 순서 3개만 먼저 읽기
  - "성경 본문을 아무 번역이나 넣어도 되나" → 개역개정은 저작권 있음. 개역한글·WEB만

### EP02 첫 화면 띄우기
- 명령어: `node -v`, `npm install`, `npm run dev`, `npm run typecheck`
- 따라 치기 프롬프트: `SPEC.md의 1단계만 구현해줘. Vite + React + TypeScript + Tailwind로 뼈대를 만들고 HashRouter를 써줘.`
- 막힐 지점: Node 미설치 / 포트 5173 안 열림 / HashRouter를 쓰는 이유(주소에 #이 붙는 것)

### EP03 말씀 데이터 넣기
- 등장 코드: `verses.json` 구조, `decks.json`, `schema.ts`(Dexie 테이블 4개), `seed.ts` 기본값
- 따라 치기 프롬프트: `요한복음 핵심 구절 24개를 개역한글과 WEB으로 verses.json에 넣어줘. 각 구절 id는 john-3-16 형식으로.`
- 막힐 지점: 번역본 저작권 / JSON 쉼표 오류 / 새로고침하면 데이터가 어디 있는지(IndexedDB 보는 법)

### EP04 잊을 때쯤 다시 보여주기
- 등장 코드: `schedule.ts`(SM-2), `cards.ts`의 `rolloverBoundary`, `bulkPut` 주석
- 따라 치기 프롬프트: `복습 화면에 다시/어려움/보통/쉬움 4버튼을 두고, 버튼마다 다음 복습이 언제인지 작게 보여줘.`
- 막힐 지점: 밤 12시 넘어 복습하면 분량이 두 번 나옴 → 새벽 4시 경계 / 카드가 두 번 생김 → bulkPut

### EP05 확인하고 내보내기
- 명령어: `npm run typecheck`, `npm run build`, `git add / commit / push`
- 따라 치기 프롬프트: `Playwright로 복습을 끝까지 한 뒤 새로고침해도 진도가 남아 있는지 확인해줘.`
- 막힐 지점: "빌드 성공 = 완성"이라는 착각 → 직접 눌러 보는 검증
- 배포: GitHub Pages(`VITE_BASE_PATH`) — 실제 배포 여부 [확인 필요]
